# 04. 메인 화면: 경영지원팀

연간 목표 대비 매출 달성 현황과 매출·매입·지출 구성을 한눈에 보는 화면이다.

## 1. 입력 항목 (확정, 웹에서 숫자로 입력)

| 구분 | 입력 항목 | 입력 주기 |
|---|---|---|
| 목표 | 연간 목표매출액 | 연 1회 |
| 매출 | 제품 매출액, 상품 매출액, 용역 매출액 | 월 |
| 매입 | 상품 매입액, 원재료 매입액 | 월 |
| 지출 | 경비 지출액, 그 외 지출액(광고선전비, 접대비 등) | 월 |
| 채권 | 미수금 통계 | 월 |

- 입력·수정 권한: 대표·경영지원팀·관리자
- 금액은 원 단위 숫자로 저장한다.
- (확인 필요) 연간 목표매출은 누가, 언제 입력하는지(연초 1회? 분기별 수정?).
- (확인 필요) 매출 기준이 계약·출고·수금 중 어느 시점인지.
- (확인 필요) 미수금 통계의 형식(거래처별 금액인지, 기간별 합계인지). 확인 전에는 월별 합계 금액 1개로 입력받는다(제안).
- (확인 필요) "그 외 지출액"을 항목별(광고선전비, 접대비 등)로 나눠 받는지, 합계 하나로 받는지. 확인 전에는 합계 하나로 받는다(제안).

### 입력 화면 (제안)

- 연도·월을 고르면 해당 월의 입력 폼이 나온다. 이미 입력된 값이 있으면 불러와 수정한다.
- 연간 목표매출액은 연도별로 따로 입력한다.

## 2. 화면 구성 (확정)

| 영역 | 표시 방식 | 데이터 |
|---|---|---|
| 연간 목표매출 달성률 | 원형(도넛) 그래프 | 목표 대비 현재 총매출(제품+상품+용역)이 어디까지 찼는지 |
| 매출 구성 비중 | 원형 그래프 | 제품·상품·용역 매출 비중 |
| 산업 분야·제품 비중 | 원형 그래프 | 생산팀이 올린 산업 분야별·제품별 판매 데이터 ([05](05-production.md)) |
| 매입·지출 추이 | (제안) 월별 막대그래프 | 매입액과 지출액 |
| 미수금 현황 | (확인 필요) 형식 확인 후 결정 | 미수금 통계 |
| AI 분석 코멘트 | 짧은 글 | 아래 4절 |
| 간이 지표 | (제안) 숫자 카드 | 아래 3절 |

- 모든 영역은 당월·분기·연간 기간 보기를 따른다([03](03-common.md)).
- (확인 필요) 산업 분야·제품 비중을 판매량(수량) 기준으로 할지 매출액 기준으로 할지.
- 지침 6장의 핵심 항목 "메인: 목표매출 달성률, 카테고리·제품 시리즈 비중 원형 그래프"가 위 원형 그래프 3종에 해당한다.

## 3. 간이 지표 (제안, 기업 확인 필요)

입력값으로 계산할 수 있는 지표다. 회계상 원가·이익과 다를 수 있으므로 화면에 **"간이 지표"**로 표시한다. 계산식은 [09-metrics.md](09-metrics.md)를 따른다.

- 총매출, 총매입, 총지출, 간이 이익, 간이 이익률

## 4. AI 분석 코멘트 (확정, 우선순위: 선택 — 2026-11-04 구현, 조원 방식)

- 이번 분기의 매출 상황, 부족한 점, 다음 분기에 개선할 점을 짧게 요약한다. 메인 대시보드·경영지원 상세 맨 위 카드(같은 기록을 봄).
- 분석 대상: 분기 보기 = 그 분기, 당월 보기 = 그 달의 분기, 연간 보기 = 확정된 달이 있는 마지막 분기. **끝난 분기만**, 확정된 달이 있어야 함.
- 계산된 숫자만 근거로 작성하고 **"AI가 생성한 참고용 요약"**임을 표시한다. 금액·비율·목표 차이는 서버가 미리 계산해 문장으로 넣어 AI가 계산하지 않게 한다. 연간 목표 한 줄과 장기 미수금 거래처명은 AI가 아니라 서버가 만든다.
- 외부로 보내는 것은 합계 숫자뿐(매출·지출·이익·목표 달성률·미수금 금액·건수). **거래처명·직원 이름·건별 내역은 보내지 않는다.**
- 외부 AI API(Claude API, `claude-opus-5-5`)는 백엔드에서만 호출한다. API 키는 `.env`의 `ANTHROPIC_API_KEY`. 화면을 열 때는 저장된 코멘트만 읽고, [분석하기]/[다시 분석]을 눌러야 호출한다(분기마다 기록이 쌓이고 가장 최근 것을 보여 줌).
- (확인 필요) 매출 데이터를 외부 AI 서비스에 보내도 되는지. **허용 확인 전 규칙(사용자 결정, 2026-11-04 — 조원 방식 그대로)**:
  - `.env`의 `AI_ALLOW_REAL_DATA=True`가 대표님 허락을 뜻한다(기본 False).
  - 허락 전 배포 서버(DEBUG=False)와 경영지원 관리 엑셀 이관 데이터가 들어간 분기는 경영지원팀도 실행할 수 없고, **관리자·대표 계정만 확인창([확인])을 거쳐** 실행한다(누르는 것이 곧 허락).
  - 개발 서버(DEBUG=True, 가상 데이터)는 키가 있으면 실행할 수 있다. 키 없이 화면 흐름만 볼 때는 `AI_MOCK=true`(모의 응답, 실패 연습은 `fail`).
  - 예시 분석: `python manage.py seed_ai_examples`가 가상 데이터로 계산한 숫자로 "예시" 코멘트를 넣는다(외부 호출 없음). 실제 데이터를 넣기 전에는 `--remove`로 지운다.
- 저장 후 데이터나 분석 기준(프롬프트 버전)이 바뀌면 "최신이 아닙니다" 안내. 같은 분기를 동시에 두 번 생성하지 않고, 그 사이 다른 사람이 분석했으면 409.
- 어려울 때 대안: 규칙 기반 문구(예: "목표 대비 n% 부족") — 예시 분석이 이 방식이다.

## 6. 제품 단가·원가 (2026-11-02, 사용자 요청 — 추가 구현 "원가·이익률"의 기초)

- 화면 `/pricing`(왼쪽 메뉴 아래 "제품 단가·원가"). **대표·관리자·경영지원팀만** — 라우터와 API(`IsFullAccess`)에서 모두 막는다. 원가·마진·커미션은 대외비(2026-11-02 사용자 결정).
- 자료: 기업 제품 가격 계산표 CSV 3개(제품 계산표, 선택 목록, 커미션). `python manage.py import_product_prices --product … --data … --commission … [--date]`로 **로컬 DB에만** 넣는다. 가져올 때 파일의 모든 금액을 다시 계산해 비교하고, 하나라도 다르면 저장하지 않는다. 배포 서버는 가상 값(`seed_product_prices`, 모델 `VX…`).
- 구성:
  1. **가격 계산 기준값**: 환율, 통관 배수, 판관비율, 마진 값, 특별할인율, 커미션율. 적용일 임시 2026-11-01.
  2. **가격 시뮬레이션**: 환율·마진 값(선택 목록)·옵션·원재료 기준(Assembly/Complete)을 바꾸면 다시 계산. **저장하지 않음** 표시, 기준 대비 판매가 차이.
  3. **제품 단가표**: 모델별 원재료(USD) → 원화(옵션 포함) → 통관 → 원가 → 마진 반영 → 판매가 → 특별할인가. 시리즈(NTI·NTIT·NTIR) 걸러 보기, 줄을 누르면 계산 과정.
  4. **커미션·이익**: 계산표에 판매금액이 있는 모델의 이익·커미션·커미션 차감 이익·마진율(제안), 모델과 판매금액을 넣어 계산.
- 엑셀 내려받기·업로드 이력·AI 코멘트에는 원가 자료를 넣지 않는다. API 응답은 캐시하지 않는다(`Cache-Control: no-store`).
- (다음 단계, 질문 답변 후) 판매 실적 수량 × 판매가로 추정 매출·추정 원가·이익률을 메인 화면 간이 지표로.
