# 10. 구현 우선순위와 일정 (제안)

한 달 안에 **"로그인 → 입력 → 대시보드 확인"이 끊김 없이 시연되는 것**을 1순위로 삼고, 어려운 기능은 대안을 먼저 확보한다.

## 1. 우선순위

| 구분 | 기능 | 어려울 때 대안 | 상세 |
|---|---|---|---|
| 핵심 | 로그인, 팀별 열람·수정 권한 | 없음(반드시 구현) | [02](02-users-permissions.md) |
| 핵심 | 실적·생산량 웹 입력 | 없음(반드시 구현) | [04](04-main-management.md), [05](05-production.md) |
| 핵심 | 메인: 목표매출 달성률, 카테고리·제품 시리즈 비중 원형 그래프 | 없음(반드시 구현) | [04](04-main-management.md) |
| 핵심 | 당월·분기·연간 기간 보기 | 분기 보기만 먼저 | [03](03-common.md) |
| 핵심 | 생산팀: 목표 생산량 달성률·부족치, 산업 분야·거래처·제품별 판매량, 일련번호 조회, 당월 납기 캘린더 | 없음(반드시 구현) | [05](05-production.md) |
| 핵심 | 서비스팀: 출장보고서 업로드 → 출장·부품·모델·담당자 집계 | 표준 양식만 지원, 또는 웹 입력 폼 | [06](06-service.md) |
| 핵심 | 관리자 페이지: 계정 발급, 권한 등록·해제, 비번 초기화 | 비번 초기화만 먼저 | [02](02-users-permissions.md) |
| 핵심 | 본인 비밀번호 변경 | 없음 | [02](02-users-permissions.md) |
| 핵심 | 서비스팀 한국 지도 점 표시 | 너무 어려울 때만 지역별 순위 막대그래프 | [06](06-service.md) |
| 선택 | AI 분석 코멘트 | 규칙 기반 문구(예: "목표 대비 n% 부족") | [04](04-main-management.md) |
| 선택 | 과거 엑셀 데이터 업로드 이관 | 정해진 양식 엑셀만 지원, 또는 직접 입력 | [03](03-common.md) |
| 추가 구현 | 엑셀/CSV 다운로드, 임시 저장, 입력 방법 안내 | 다운로드 먼저 구현 | [03](03-common.md) |
| 추가 구현 | 원가·이익률, 매입·매출·미수, 자금수지 예측(3~6개월), BEP 달성 현황, 생산량·공장 가동률, 수주 잔고·영업 파이프라인, 인당 생산성 | 실제 데이터가 없는 지표는 가상 데이터로 화면 구현, 끝내 못 한 지표는 발표에서 향후 계획으로 소개 | [09](09-metrics.md) |

순서 원칙: **핵심 → 선택 → 추가 구현**. 기업이 확정한 기능을 먼저 완성한다.

## 2. 4주 일정

| 주차 | 목표 | 주요 작업 | 주차 말 확인 기준 |
|---|---|---|---|
| 1주차 | 요구사항·데이터 확정 | 질문 목록 전달, 샘플 엑셀·출장보고서·그래프 레퍼런스 확보, 개발 환경 세팅(Vue·Django·PostgreSQL, 사용자 모델 확장), 데이터 구조(테이블) 설계(원가·매입·수주 등 추가 구현 지표 항목 포함), 가상 데이터 작성 | 화면 목록과 데이터 구조 팀 합의 |
| 2주차 | 뼈대 + 메인 화면 | 로그인·권한, 실적 입력, 메인 원형 그래프 3종, 분기/월별 전환 | 경영지원팀 계정으로 입력 → 메인 그래프 반영 시연 |
| 3주차 | 생산팀·서비스팀 | 생산 실적 화면, 일련번호 조회·납기 캘린더, 서비스팀 출장보고서 업로드·추출·집계, 서비스팀 지도 또는 지역 순위, 관리자 페이지 | 팀장/팀원 권한 차이와 업로드 집계 시연 |
| 4주차 | 마무리 + 발표 | AI 코멘트, 과거 데이터 이관, 추가 구현 지표(원가·이익률, BEP, 자금수지 예측 등), 오류 수정·테스트, UI 정리, 발표 자료·시연 시나리오 | 처음부터 끝까지 리허설 1회 이상 |

- 1주차에 기업 자료와 답변을 확보하지 못하면 이후 일정이 모두 밀리므로, **질문 목록([11](11-open-questions.md)) 전달을 가장 먼저** 한다.
- 매주 말 기업 또는 멘토에게 진행 화면을 공유해 방향이 맞는지 확인한다.
- 3주차 말까지 핵심 기능이 안 되면 4주차의 선택 기능은 과감히 빼고 안정화에 집중한다.

## 3. 1주차 개발 환경 세팅 순서 (제안)

1. `backend/`에 Django 프로젝트 생성, DRF 설치
2. PostgreSQL 연결 (접속 정보는 `.env`)
3. `accounts` 앱에 `AbstractUser` 확장 모델 작성 → `AUTH_USER_MODEL` 설정
4. **그 다음에** 첫 `migrate`
5. `frontend/`에 Vite + Vue 3 프로젝트 생성, Bootstrap 5.0 설치
6. 화면 → API 호출 1개(예: 로그인)로 연결 확인
7. `.gitignore`에 `.env`, 실제 기업 데이터 파일 경로 추가 후 첫 커밋

## 4. 판단 기준

새 기능 아이디어가 나오면 핵심·선택·추가 구현 중 어디에 속하는지 먼저 분류하고, 일정상 무리면 더 단순한 대안을 고른다. 판단 기준은 기업 요구와의 관련성, 구현 난이도, 팀원 기술 수준, 기존 기능 영향, 시연 가능성이다.
